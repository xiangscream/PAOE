# PAOE 开发准则

适用范围：本仓库代码、测试与随包文档。先读本文件，再读 [当前架构](../../../ARCHITECTURE.md) 和 [代码地图](CODE-MAP.md)。业务操作方法以已登记共享 Workflow 的唯一正文为准，不在源码复制第二套规程。

## 1. 先守 SSOT 与事实归属

- Project Registry 只保存 Project Vault 的定位、Home 名册和 Coordinator，不保存项目摘要、任务或进度。
- Project Vault 保存项目业务事实；INDEX.md 是导航入口，TEAM.md 是当前成员职责来源。
- Agent Home 的 TODO v4 保存本人当前责任；Mail 保存持久消息原件；Notice 保存输入处理事实。
- Workflow / Skill / Tool 的 Markdown 源文件是权威，Catalog 是可重建索引。
- 前端、CLI、报表和缓存只能展示或调用原件，不得创造第二份业务真相。

修改前先回答：这份事实归谁、原件在哪、当前写者是谁？

## 2. 保持最小实现

先评估现有标准库和模块是否足够。当前核心以 Python 标准库、JSON、Markdown 和原生 JavaScript 为主；不要仅为“看起来专业”引入 ORM、前端框架、任务队列、服务网格或复杂状态管理。只有真实需求超过现有能力时，才提出新依赖，并说明它减少了什么长期维护成本。

## 3. 按增量交付

每次只增加一项可验证能力。先明确用户动作和完成条件，再实现最小闭环。没有清楚用户收益的抽象层、状态库和后台服务不提前建设。代码拆分不是目标；减少隐含依赖、重复状态和错误路径才是目标。

## 4. 遵守模块与写者边界

| 层 | 负责什么 | 不应做什么 |
|---|---|---|
| portable.py | 本机安装定位与可选画板启动 | 创建业务 Project / Home |
| scripts/paos.py | CLI 参数、命令装配、结果与错误出口 | 复制领域规则或绕过写者 |
| scripts/paos_*.py | 各领域的校验、读写和服务语义 | 越权写入其他领域原件 |
| paos_registry.py | 五字段 Project 定位登记 | 变成项目业务数据库 |
| Home writers | TODO、Mail、Notice、激活等各自负责的原件 | 互相代写或创建并行状态 |
| front/ | 读取与展示，少量动作调用既有 CLI / CAT | 实现第二套业务写者 |
| Shared Workflow | 可复用工作规则与操作流程 | 把业务状态存入方法库 |

修改前沿调用链找到现有写者。不要因为一个前端按钮或 CLI 命令就再造一份数据写入逻辑。

## 5. 根据爆炸半径设置验证

以下情况必须有阻塞测试：可能静默覆盖、损坏或丢失用户原件；修改 Project / Home / Mail / Notice / Contact / Library 公共合同；修改路径解析、跨 Project 路由、身份校验或重复请求语义；修复曾经真实发生且容易复发的用户路径故障。

局部展示文字、样式或单一帮助文本按影响范围做定点检查，不自动升级成全量架构审查。

## 6. 写入必须可见、可定位、可恢复

- 结构化输入先校验身份、schema 和必需字段。
- 有指纹保护的原件不得绕过预期指纹写入。
- 对需要保护的文件写入沿现有锁、临时文件与原子替换路径。
- 失败时说明文件、字段、原因；不把未知结果说成成功。
- 外部调用超时后先核对原件或服务端结果，不盲目重发。

不要把“文件存在”“消息已投递”“提醒受理”“Agent 已接手”混成同一个成功状态。

## 7. 个人单机威胁模型，不提前支付不存在的复杂度

当前设计前提是个人使用、本机文件、服务绑定回环地址。保留真实需要的保护：不提交私有数据与凭据、服务默认只监听 127.0.0.1、原件写入保护、错误可见。

在多用户、跨设备并发、开放局域网、远程 API 或公司数据接入成为真实需求前，不预建复杂 RBAC、分布式锁、后台调度和多租户安全体系。

## 8. 文档与代码必须同步

当前文档只描述当前实现；历史设计、旧运行记录放入 docs/history 或明确标记为历史。修改模块职责、命令、schema 或写入边界时，更新对应代码地图或合同入口。导航页只做导航；唯一规则正文不要复制成多份。CI 通过只证明 CI 覆盖范围内的结果，不代表生产 Home 或真实 Runtime 已采用。

## 9. 验证入口

~~~sh
python code/personal-agent-os/scripts/verify.py
node --test tests/board-ui.test.mjs
~~~

运行时不需要 Node；Node 命令只用于画板显示逻辑的辅助测试。真实业务采用按 MIGRATION-NOTES.md 与当前安装指南单独执行。
