# 夜间整理

<!-- paoe:human-intro:start -->
> [!info] 给使用者
> 一天工作结束后，可以按这份流程整理当天成果、修正当前入口，并留下第二天能够接着做的线索。
>
> **从这里开始：** 按下面的适用范围和步骤使用；需要执行时让 Agent 从“操作与参考”继续。
<!-- paoe:human-intro:end -->

<!-- paoe:agent-reference -->
## 操作与参考
<!-- paoe:reading-header:end -->

把白天的成果整理成明天能直接接续的入口。日常维护先由产出者或采用者在实际交付中按[Project 文件与 Git 的日常顺手维护](guide-project-work-world.md#日常顺手维护)完成；本流程主要补漏、解除旧等待并把有效经验并回唯一正文。执行者处理遗漏的文件归位、明显失效的入口和普通软修；业务 Owner 维护任务状态与业务判断；Rooter 分配范围、处理运行问题并复核结果。

日间输入整理复用日常输入整理（`<workflow_root>/Workflows/wf-meeting-audio-package.md#默认工作循环`）：
只补未处理的对话、日会和 Tips，更新已有口径或行动，不强制生成独立日报。

## 开始一批

沿当前项目 `AGENTS.md` 的公共运行区恢复本人责任。先接上次未完批次，再看当天有变化的 Project、TODO、成果和 Library；只打开本次需要的原件。

选择本次有变化或尚未处理的对象，在本人 Current 写清要取得的结果。两次维护分别侧重下面一项检查；未完责任沿原任务接续，同一偏差只交原 Owner 一次。已修好且没有新变化的内容不重复检查。

## 经历与项目口径

从有实际进展的 TODO、成果与原始输入出发，对照相关日期的个人经历，以及 Project 的 INDEX、HISTORY：

- Human 的实际工作、判断和学习是否已有记录；技术团队和 Agent 的执行分别归属，完成日期保持真实。
- 新决定、成果和后续安排是否进入当前项目口径；已结束的等待是否还被写成下一步。
- 完成项是否已归入历史并关联原件；经历中的项目摘要是否带来源和日期，能否回到当前项目。

经历整理沿日常输入方法和原合成人继续，不另写一份日报。项目业务口径由原 Owner 更新；日期快照只作背景，不能代替当前登记或本人 TODO。没有新进展的项目不要求每天改页，文件较旧本身不构成遗漏。

## 库与 TODO 卫生

检查有变化的 Project、System、Libraries 和工位，补日常维护遗漏：

- 采用的录音、下载和导出是否已归原项目或可复用资料包；入口能否找到正文。
- TODO 的 Current、未完任务与实际结果是否一致；完成项、旧在途和重复 TODO 是否已整理。
- 过时过程件、已处理 Mail/Notice 和替代稿是否退出活跃库；库外历史是否有简短入口，当前引用是否可用。
- 共享规则是否重复、冲突或指向退役入口；专业方法和工具配置能否直接找到并复用。

按[Project 文件与 Git](guide-project-work-world.md#日常顺手维护)处理具体文件。普通归位、导航和软修直接完成；本人更新本人 TODO，业务取舍交 Coordinator。保留当前依赖，历史移到库外，不为整理重开实验或重启服务。

## 回用与接续

具体偏差先修正；反复摩擦合并到 Rooter 的既有摩擦页，记录发生位置、影响和本次处理。能改进唯一 Workflow、Guide 或 Skill 的就直接改，并同步引用；后续真实工作效果不好时修正或回退。

结果留原任务或成果入口：做了什么、还缺什么、由谁接续。收口综合任务时，先把仍需行动的责任接到本人未完 Task，再将已完成部分归历史。Current 指向对应 Task 的下一动作或真实外部依赖，不另造日报或重复台账。共享正文沿一位维护者；产品代码交 S010 组织，安装运行交 Rooter。对方已接手或正在工作时不重复提醒，接续按实际成果或明确业务节点进行。

## 运行条件

具体工位、时间和结果路径放在本安装的任务交接中；自动任务只负责唤醒与定位本流程。维护变化记录在原 Project 或本人任务中，平稳无变化时保持安静。

模型按当前授权和产品实际状态选择。夜间免费活动须核当前标志、有效期与时间窗；延迟执行时按实际时间判断。提前保存 Current 和成果，再按模型容量压缩或换 Runtime；恢复顺序沿工作循环。

入口不可用时保存本批次与首次回执，由 Rooter 沿已有正常路径恢复。未知交付先查原记录；受理、本人读件、实际修改和接受分别按真实结果记录。
