# Runtime 接班与在途外部写入

<!-- paoe:human-intro:start -->
> [!info] 给使用者
> 当 Agent 需要更换会话、进行上下文压缩，或将任务交给下一位接班者时，本指南确保已有成果不丢失、在途外部写入受控，并交清下一步。
>
> **从这里开始：** 查阅下方会话压缩、交接内容与外部写入保护三项规范。
<!-- paoe:human-intro:end -->

<!-- paoe:agent-reference -->
## 操作与参考
<!-- paoe:reading-header:end -->

消息唤醒后恢复的是 Agent 的**已有完整岗位责任**，不仅是一次收件动作。Runtime 应读取固定 ENTRY 与 TODO，推进主线可执行任务，仅在确有外部依赖或阻碍时等待。

---

## 1. 会话压缩与薄状态恢复

1. **压缩前固化状态**：
   - 本人在执行压缩前，必须将当前成果原件、在途操作、以及接续所必需的上下文固化到工位 `TODO.md` 的 Current 与 Tasks 中。
   - 避免将长篇过程草稿堆在当前会话；必要事实写入正式文件。
2. **压缩后恢复（Orient）**：
   - 压缩或新会话启动后，执行本工位 ENTRY 的恢复命令（`orient <project> <Sxxx> --read` 或 Codex 的 `--resume`）。
   - 完整读取返回的 AGENTS、INDEX、ENTRY、TODO，以最新原件纠正压缩摘要可能带来的偏差，立即接续 Next action。

---

## 2. 交班责任清册

更换会话或接力时，当前 TODO 必须交清六项事实：
1. **真实目标与当前阶段**（做到哪里）。
2. **下一项立即可执行动作**（Next action）。
3. **外部依赖与等待项**（Waiting，收到后如何接续）。
4. **成果与业务原件入口**（Result refs / Artifact，稳定路径或链接）。
5. **在途操作与未完调用**（Inflight）。
6. **接班负责人**（明确由谁接手）。

成果已有交付文档或链接时直接引用它，不另造冗余的 Handoff 笔记。

---

## 3. 跨回合外部写入保护

当启动可能跨越当前回合继续修改飞书、本地文件或外部系统的进程/脚本时，必须明确交代：

- **写入目标与当前基线**：如飞书文档 Token、当前 Revision，或目标文件路径。
- **调用入口与停止方式**：执行的命令、PID、停止脚本或中止机制。
- **控制人与查看位置**：谁在控制、运行日志与回执保存在哪里。
- **任务范围与终止条件**：预期何时结束，达到何种结果时停止。

### 交接结论要求
交接结论只能明确表述为以下三者之一：
- **已完成**：并已回读核验外部实际结果；
- **已停止**：并已确认外部写入已终止；
- **仍在进行中**：明确由哪位同事或进程接管。

状态未知时必须如实报告未知与最后已知现场，严禁以“本轮未操作”掩盖上轮未决的外部副作用。
