# Project 文件与 Git

<!-- paoe:human-intro:start -->
> [!info] 给使用者
> 这份指南说明资料、成果和经验应该放在哪里，以及什么时候记录版本。它帮助你和 Agent 维护一份容易找到的项目资料。

## 操作与参考
<!-- paoe:reading-header:end -->

项目文件承载正文、输入、判断与成果；工位保存当前行动，PAOS 提供定位、读写和联络。文件整理服务下一位读者，不要求完整归档仪式。

## 放在哪里

| 内容 | 正常位置 |
| --- | --- |
| 当前正文、分析、复核、交付 | Project 的 Works / Decisions 或已有对应目录 |
| 已采用的本地录音、下载、截图、导出及外部输入快照 | 项目已有 Materials/主题目录，保留原文件与必要来源 |
| 外部 live 飞书、共享源码/资料 | INDEX/成果中的直接引用，不冒充可写副本 |
| 本人 ENTRY / TODO / Mail / 可选笔记 | 固定 Workstation |
| 工具绑定、缓存、原生聊天 | Runtime/安装配置，不混进正文 |
| 结束的过程件、旧版本、已归档通信记录 | 库外项目历史目录；Project 内 HISTORY/Archive 只留简短导航 |

Project 根的 INDEX 保存最新业务口径并链接必要原件，AGENTS 保存运行规则，TEAM 集中成员职责、Harness 和工位。最新口径服务 Agent 对齐；不另填 human/generated 或项目简介。目录按真实用途建，不为模板创建空树。Working Memory 有用内容成为普通文件；同一结论已经在报告里就引用它。

## 当前页与历史

本人负责自己的当前入口。替换文稿时更新 INDEX/成果引用，让旧稿退出 current；长过程从 TODO 移到已有报告或历史。无法判断哪个正文生效时找 Coordinator，不按文件名或修改时间猜。

Project 根的 HISTORY 按业务主题汇总阶段成果、关键判断和经验。项目合成人读取成员已完成 TODO 与实际成果，将同一主题的多轮修改合并，保留日期或阶段及原件链接。日常总结或阶段交付时同步 INDEX 的最新业务口径与成果入口，清理已结束且无在途依赖的过程材料。详细历史放库外，工位 ENTRY 与项目 INDEX 指向同一 HISTORY。

任务行动与进展在对应工位 TODO，项目共识在唯一最新口径；不在 Project JSON 维护第二份进展。任务完成与成果接受按实际结果区分。参考快照注明来源即可，不给普通资料增加逐文件哈希和必填 provenance 账本。

每个独立交付阶段保留审阅时原文、必要交付回执和移动恢复映射；常规 Current 写入不逐次另存 TODO 全文、指纹或目录快照，异常时保留对应现场。同类已定用途资料按实际用途合批，复用现有阅读与恢复入口。

完整回放、恢复副本和测试资料树放在活跃Vault之外。项目内保留当前输入、正式成果和简短历史入口，避免把每次实验的整库副本、旧工作树和依赖目录带进Obsidian索引。

### 日常顺手维护

维护放进实际业务动作，不留到统一大扫除：

| 触发 | 采用者或产出者同时完成 |
| --- | --- |
| 收到并采用本地材料 | 把明确属于项目的文件从 Downloads、桌面、临时附件或导出目录归入已有主题位置；保留可追溯来源，后续使用入库原件。 |
| 形成、接受或替换成果 | 更新 INDEX 的对应入口、本人 Current 与完成项；旧稿退出当前导航，共享 INDEX 由约定的一人合并。 |
| 结束一批工作 | 将无在途依赖的旧过程件按既定历史位置移出活跃库，保留必要原件与一份批次映射；发现明确遗漏就补齐。 |

不要仅为了归位另造一份录音或转码副本。仍被程序使用的文件先处理其引用；共享原件或云端权威内容沿稳定入口使用。归属不清的材料先放项目 Inbox 并交 Coordinator 判断，不顺手猜用途或清空下载目录。普通归位直接执行，不逐件等 Rooter 验收。

### 工位收敛

每个Home只有一份当前`TODO.md`。ENTRY负责导航，TODO负责行动；个人规则仅保留项目指南未覆盖的真实差异。当前Contact、正常工具和必要笔记按实际用途保留，母版不是删除文件的白名单。

旧Assignment、Handoff、TODO备份和写入载荷不留作当前入口。有未完责任先由本人接入当前TODO；结束且无依赖的文件移到项目库外历史，保留成果与位置映射，修正现行引用。旧版本迁移JSON、快照和已失效等待退出恢复正文；Mail/Notice走正式归档接口。

每天汇总本人经历时，顺手整理完成项、下一动作、工位与当天采用的材料。项目合成人据实际成果更新INDEX/HISTORY；能直接修的小摩擦当场修，可复用问题回安装Rooter现有摩擦页，说明实际场景、影响和处理结果。

本机Libraries与工具导航放AGENTS公共区外，从已登记库根填写直接链接；创建或库根变化时同步。共享规则仍只维护公共母本，机器路径不写进共享正文。

### 库外历史

库外历史是 Obsidian Vault 之外的实体目录，可在项目旁设 `<项目名>-History`，磁盘紧张时采用安装安排中的历史盘。项目 INDEX/HISTORY 写明唯一位置。不要通过目录链接把历史重新挂回活跃 Vault，也不要给每个旧文件再造一份占位文档。

保留当前业务正文、仍需直接使用的原始材料和当前任务引用；退出的是已经结束的过程和退役版本。归档批次保留原相对结构、用途和原位置到新位置的一份简短映射，更新当前有效引用。历史记录中的旧路径按映射追溯，不为搬迁重写已接受内容。

Mail/Notice 按官方合并读面判定已读、已处理和在途依赖；仅有 archive 标记不代表文件已移出库。使用当前安装提供的通信归档操作保留正文、状态及后续查阅入口；接口未提供的部分交产品维护者补齐，不能把仍在使用的 Mail 或 sidecar 当普通散件搬走。具体操作只维护在通信指南。

## 准则登记与退役

会指导 Agent 行为的文件必须能从现有入口找到：Project 规则登记在 INDEX 的当前入口；Workflow / Skill 以既有元数据登记进各自 Catalog。登记只说明主题、现行路径及适用范围，不复制正文，不另建登记系统。普通草稿、原始输入和个人临时笔记无需登记成规则。

一个主题只维护一份现行准则。工位、AGENTS、模板与其他指南只链接对应章节；环境差异在同一准则内说明，不复制一本。修改规则时，沿登记入口和旧名称、路径、关键术语检查引用它的 Project、Workflow、Skill 与实际 Harness 入口，一起处理被替代的口径。

移动原件时更新当前入口与仍使用它的引用；已有交付和版本证据照常保留，不为每次归位另建 Artifact 登记。Windows 归档按[文件移动操作](guide-tool-pitfalls.md#powershell-文件归档)执行，移动报错时保留源文件并处理错误。

被取代的正文移出 current：有追溯价值的放库外历史目录或使用 Git 固定版本链接。历史材料标明历史，不继续自称“当前/唯一合同”；有效证据与原始日志保持原样。能从 Git 恢复的重复副本无需再堆一份归档。

升级收口在原有交付记录写清现行来源、退出的旧入口和剩余例外，并从实际入场路径回读；不增加独立审批或每人一份自查报告。Workflow / Skill 源文件变化后重建 Catalog，保留使用记录。若两份内容是否仍有效涉及项目判断，交 Coordinator 确定；确定后的引用与归档清理由维护者完成。

## 关联更新

每项事实只维护一个原件；各入口直接给出本职必要的身份、操作、输入和失败断点。按实际变更类型处理：

| 类型 | 必须联动 |
| --- | --- |
| 执行接口：路径、命令、字段、消息格式、状态语义 | 更新实际使用该接口的 ENTRY、模板、脚本或示例；实际调用验证。 |
| 派生内容：AGENTS 公共区、PROJECTS、Catalog | 使用现有分发或生成器重建、检查，保留人工区。 |
| 专题解释：Guide 与普通说明 | 更新唯一正文和失效直接链接，其它入口保留必要的用途说明。 |

先用旧路径、命令、字段名查受影响使用方，再按范围修改并保留人工内容。母版检查沿 [母版说明](../Project-Template/README.md#修改后检查)，PROJECTS 刷新沿 [本页更新入口](../PROJECTS.md#更新与检查)。校验链接不等于实际业务或唤醒已通过。

## 项目文本 Git

已登记项目的正文、INDEX、TEAM、工位 ENTRY/TODO、项目规则可进入项目自己的本地 Git。System、独立 Project 和 Libraries 按实际 Git 根维护。

System 的整体同步范围包括 Core、Guide、Project-Template 和 rooter 的可共享入口；项目业务源码如另有独立仓库，以该仓库为准。Rooter 是 System 内的安装级 Home，不另算一个 Project，也不要求独立建仓库；私有配置、Mail/Notice、会话绑定和备份不随公开同步。本机现有 Core checkout 与 Git 历史不因本文调整而迁移。

回退以实际所在仓库的历史和安装恢复点为准；跨层版本配对读共享安装说明。Windows/WSL 的行尾差异须按实际 Git 宿主核对，不据整文件伪差异覆盖他人编辑。

排除 private-data、运行绑定、缓存、密钥配置、大媒体与原生聊天；Workstation mailbox/log 是否跟踪按安装隐私与真实恢复用途决定，不把整棵 Runtime 目录收进 Git。共享目录提交前读差异，只提交自己负责的路径或 hunk，不用 `git add .` 带走同事修改。提交时区分本轮自己负责的成果与入口，不混入同事或先前批准范围外的改动。

Git 域按明确授权的项目边界与居民协议固定；同一仓库被多个工作树（含 Windows/WSL 混宿）共用时，登记修复只由实际归属 Git 宿主执行，不跨宿主 `worktree add/prune`，不删对方 `.git` 指针；误损先报告原宿主维护者并回执修复。

在有意义的进展或交付处提交，给出做了什么。冲突查看双方新内容再合并；不会处理时请同事一起解决，不整文件覆盖。Git 提供版本、差异和恢复，不手抄 Git log，也不能回滚飞书的外部写入。

## Project 经验原件

Project 自己的经验默认归 `<登记根>/Materials/TIPS.md`：普通 UTF-8 Markdown，由 Owner 通过正常文件/Git 维护，记录实际场景、做法/结论、依据与适用范围，用明确标题或锚点定位条目。它是该项目经验的唯一读取入口；没有经验不凑条数。已有其它经验文档不自动搬迁或合并，Owner 可在入口指向真实原件，读者自行打开。

只读回用：`paos project experience <project_id>` 读取本项目的经验 Markdown；没有文件就明确缺失。写入仍走普通文件/Git。跨项目有效经验再吸收到唯一 Workflow 或 Skill，不同步第二份项目经验库。

多人修改沿原 Project 文件/Git 协作，出现差异由作者合并，不能最后写者覆盖他人；Core 不提供写锁或跨文件事务。

## 归档与边界

Coordinator 判断项目内容与团队责任，Rooter处理安装、跨项目运行与旧项目退出。Human 明确保留的主稿或方向取舍仍遵循其要求。普通成果归位和个人当前页维护无需逐文件审批。

旧 Project 退出 active/自动运行时保留历史与引用；仍使用的共享资料原位保留。归档不改历史责任状态，不重新 onboarding 历史成员，不为目录整齐搬整个 Vault。
