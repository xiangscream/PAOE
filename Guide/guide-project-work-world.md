<!-- paoe:agent-reference -->
## 操作与参考
<!-- paoe:reading-header:end -->

项目文件承载业务正文、输入、决策与成果；工位保存当前行动。文件整理服务于下一位接手者，不搞繁冗仪式。

---

## 1. 放在哪里

| 内容类别 | 规范位置 | 说明 |
| --- | --- | --- |
| 当前业务正文、分析、复核与报告 | `Works/` | 过程件与正在成型的成果；稳定后移入 Decisions 或链接至 INDEX |
| 正式决策、被接受的结论与基线 | `Decisions/` | 项目形成的权威决议与正式方案 |
| 原始录音、下载、截图、外部附件快照 | `Materials/` | 保留原文件名与必要来源；项目经验默认归 `Materials/TIPS.md` |
| 尚未确认归属的临时输入 | `Inbox/` | 待分类材料暂存处；由 Coordinator 明确去向 |
| 外部 live 飞书、共享源码与云端文档 | `INDEX.md` 或成果正文中的稳定链接 | 保持云端权威，不造本地冒充副本 |
| 本人 ENTRY、TODO、Mail、私有笔记 | `Workstations/<Sxxx>/` | 各自独立工位；TODO 仅维护当前未完责任 |
| 已结束的过程材料、旧版本快照 | 库外历史目录（如 `<项目>-History`） | 活跃 Vault 内仅留简短索引，避免膨胀 Obsidian 索引 |

---

## 2. 当前态与库外历史

1. **唯一最新口径**：项目根的 `INDEX.md` 保存最新口径并链接必要原件。成果替代时更新 INDEX 链接，让旧稿退出 Current。无法确认哪个正文生效时请 Coordinator 裁决。
2. **阶段成果归并（HISTORY.md）**：由项目合成人汇总成员已完成的 TODO 和交付成果，按业务主题合并记录，保留时间与原件链接。
3. **库外历史（History Vault）**：
   - 库外历史是活跃 Obsidian Vault 之外的独立物理目录（如在项目旁设 `<项目名>-History`）。
   - 已结束且无在途依赖的过程件、旧批次交付移入库外历史，库内仅保留简短映射。
   - 不通过软链接把历史重新挂回活跃 Vault。

## 日常顺手维护

维护融入日常业务动作，不留到集中大扫除：

| 触发场景 | 采用者或产出者当场完成 |
| --- | --- |
| **采用本地材料时** | 将明确属于项目的文件从 Downloads、桌面或临时目录移入 `Materials/` 对应主题；后续使用入库原件。 |
| **交付或替换成果时** | 更新 `INDEX.md` 对应条目、更新本人 Current 与完成项；旧稿退出当前导航。 |
| **结束一个阶段时** | 将无在途依赖的过程件移入库外历史，归档本人已完成 TODO，保持工位清爽。 |

## 4. 准则登记与修改联动

- **单点权威（SSOT）**：每项规则仅在一处维护正文。修改某项规则时，沿登记入口检查引用它的文件，同步消除被取代的旧口径。
- **关联更新规范**：
  - **执行接口变更**（命令、参数、字段）：必须联动更新使用该接口的 ENTRY、模板、示例，并实际调用验证。
  - **派生内容变更**（AGENTS 公共区、PROJECTS）：使用对应生成器或分发工具更新，保留人工编辑区。
  - **专题解释变更**：直接修改对应 Guide，外部只留简明用途说明与链接。

---

## 5. 项目文本 Git

已登记项目的正文、INDEX、TEAM、工位 ENTRY/TODO 与项目约定可纳入项目本地 Git 仓库。

- **排除范围**：排除 `private-data`、运行配置、Token、缓存、大体积媒体和原生会话目录。
- **提交粒度**：只提交自己负责的成果与路径，不使用盲目的 `git add .` 带走同事修改。提交信息写清实际改动。
- **差异与合并**：跨 Windows/WSL 编辑时注意换行符（CRLF/LF），避免整文件虚假 diff。冲突时查看双方新内容再行合并，禁止直接用己方版本整文件覆盖。

---

## 6. Project 经验原件（TIPS.md）

- 项目自身沉淀的经验默认归入 `<项目根>/Materials/TIPS.md`。
- 采用标准 Markdown 编写，记录真实场景、做法结论、依据与适用范围。
- 检索方式：通过 `paos project experience <项目ID>` 直接读取。跨项目可复用的成熟经验，进一步提炼为 Libraries 的 Workflow 或 Skill。

## 升级与旧入口退役

每类内容或运行数据只认一个正式来源，使用方通过该入口读取。升级时把有效内容一次迁到新位置，同批更新使用方并验通正常读写，随后撤下旧入口。独有历史放库外归档；运行只依赖现行 SSOT。
