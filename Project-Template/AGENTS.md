## PAOE · Agent 运行指南

PAOE 是 Human 和多名 Agent 共同工作的本地环境。Human 给出目标、做关键取舍。Agent 结合已有经历和方法独立推进，需要配合时直接找同事。一个阶段结束，接手的人应能从原件看懂为什么这样做、做到哪里，以及接下来做什么。

| 要做的事 | 去哪里 |
| --- | --- |
| 恢复工位、联系同事、查运行规则 | **System** 提供工位入口、联系工具、通用指南和模板。 |
| 查这个项目现在怎么做、依据是什么 | **Projects** 的每个项目库保存当前业务口径、材料、成果和团队分工。 |
| 找已有做法，或把管用的改进交给下一个人 | **Libraries** 保存可复用的工作流、专业技能和工具用法。 |
| 想起以前类似的事，找到当时的原话与取舍 | **EXM** 保存跨项目经历和团队背景。用关键词或向量语义检索找到相关经历，再回到原文。 |

### 1. 从当前任务恢复

新会话、接班或压缩后，从本人 ENTRY 取得 CLI 前缀。已登记 Codex 接收器的本人，在原 Desktop 工具环境先执行 `wake prepare-current`；其他 Harness 沿 ENTRY 的正常入口。随后执行 `orient <project> <Sxxx> --read`，将当前 AGENTS、项目 INDEX、本人 ENTRY/TODO 的完整输出读入本轮上下文，再读当前任务所需原件。准备失败时保留具体错误交 Rooter，继续可独立完成的责任。摘要只帮助定位。Rooter 直接读本人工位和 System 入口，不虚构项目。

共同经历（EXM）是持续维护的外置记忆。恢复本人 Current 和当前输入后，在写新 TODO 或第一份实质计划前，读完页首“共同经历”中的短背景；进入新阶段、压缩恢复继续规划时也先读。主动联想可用的跨项目结论、成果与相关同事，结合本任务推进。

具体检索读同处的“本机 EXM 方法”：明确名字、术语用词面检索，概念问题按任务意义宽召回，需要时精排；定位后读原文上下文与后续纠偏。词面零命中时，换说法、检索方式或沿已有来源追读。历史贡献沿原件找人，当前责任和业务口径读 TEAM、项目 INDEX。

项目用项目编号，人员用全局员工号（如 S067）。找同事、交接任务和进入项目工位都用员工号，工位目录为 `Workstations/Sxxx`。跨机联系时说明对方所在机器，由该机登记找到员工。Rooter 通过 System 的安装入口联系。

从本人TODO和当前有效输入确定下一动作，同事记录用于补事实。普通通知和维护并入原责任，不打断Human明确的当前优先级；改变目标、解除阻碍的输入及时接续。已完成的旧议题只按需查结果。

### 2. 把责任落到 TODO

需要行动的新输入或返修，先接入本人TODO的相应未完Task；确有新责任时再新增，校准Current后推进。Pinned 留持续要求，Tasks 留行动和结果，Current 只写现在要做的事：

- 目标：本次要取得什么结果。
- 下一步：一项能直接开始的动作。
- 等待：缺谁的什么输入、收到后怎样继续；没有就留空。
- 在途：已经发出而尚未完成的操作；未来计划不算在途。

本人维护 TODO。只改 Current 用 `attention todo-update`；改 Tasks/Pinned 用同版 `todo-write` 和原文指纹，冲突先重读。状态、时间和完成结论取自实际结果。读信、处理 Notice、完成任务分别记录。

### 3. 用已有方法和工具推进

已授权的简单直接修改，由执行者自查后直接完成，不增加前置审核。方法与工具从页首“Libraries 与工具”的直接链接进入：Workflow查工作流，Skill查专业做法，Tool Catalog查本机工具和已有配置。不熟悉的任务先查相关目录，或用 `paos library search "任务关键词"` 定位并实读命中的原件；工具也可用 `paos library tools` 查询。确认调用环境后复用已有配置。

路径取 ENTRY、登记或真实返回值；普通操作先查同版 `--help`，不靠翻源码重新发现接口。找不到公开入口或出现错误，保留具体断点并找适当维护者，继续其他可执行部分。需要同事时读TEAM或`paos peers`。Coordinator主要负责总体安排、优先级、方向和跨成员配合；成员自主推进，普通修改不逐项等批。需要方向取舍或解决协作阻碍时找Coordinator，安装和原生接收找Rooter，专业问题直接找对应负责人。

### 4. 阶段完成或交接时整理成果

采用下载、录音或导出时，将业务原件归入Project材料目录；跨项目可复用的方法与参考资料按Libraries既有收纳规则归位并关联入口。修正引用，云端权威原件保留稳定链接。

完成一个阶段，或把未完工作交给同事时，在本人 TODO 写明做到哪里、成果原件在哪、接下来由谁做什么。项目合成人把已形成的决定和成果更新到 INDEX，将阶段结果归入 HISTORY。同一主题接着原条目写。

- **Human 直接参与时**，执行者按 Libraries 的 `session-extraction` 整理本阶段意图稿。从上次交付处接续，按对话顺序保留这段范围内的 Human 原话，每轮简记 Agent 实际做了什么、交了什么。关联本次产物和会话来源，让接手者能回看目标、取舍和纠偏的来由。
- **Agent 独立完成时**，写清执行者、实际工作、结果和原件来源，直接交这份成果记录。已有 TODO 或成果页写全了，就引用原条目。
- **交给谁**。交接业务时，把成果、相应意图稿和下一动作给接手人。同时把同一份来源和成果入口交 EXM 的 TEAM 所列整理负责人。EXM 整理者把 Human 的参与归入对应日期和事件，把 Agent 的独立工作按实际作者归档。将相关的经历连起来，有新判断再更新短背景，本批入库后刷新检索索引。

在同一次阶段完成或交接中整理工位。归档本人已完成的 TODO，留下未完责任，将失效入口和已结束的过程件移到库外。遇到重复配置、难找的资料或恢复失败，能顺手修的当场修，其余带具体案例反馈 Rooter。

AGENTS 维护运行规则，INDEX 维护当前业务，TEAM 维护成员分工与 Harness，HISTORY 汇总阶段成果。共享文件明确一位合成人。

项目库保留当前业务、有效材料和接续入口。结束且没有在途依赖的过程件及旧 Mail/Notice，按现行文件/接口指南移到库外历史，库内留短索引。直接移动已确认的准确路径；报错就停该次移动，不接着删除源件。

### 5. 交接并持续改进

需下游行动时，用 `agent send --remind` 一次交清第四节的材料和下一动作。对方已接手后，按实际成果、失败回告或约定节点接续。投递状态不明时查原消息一次。多人讨论用 CAT，行动回本人 TODO，结论回项目。

Human询问进度或要求更新快照时，先依据当前成果给出简短结果并更新原入口；缺的部分写实际待办，不等其他任务收尾或重新审全文。新指令明确改变优先级时，立即校准Current并先做该动作，完成后接回原责任。

交付一个阶段后，继续当前授权内能做的下一步；只有没有可执行责任或确有外部依赖时等待。压缩前保存 Current、成果和在途操作，沿 Harness 正常入口压缩，完成后回第 1 步。

发现重复劳动、失效入口或难用说明，先解决当前事，顺手修已授权的小项。可复用改进回唯一方法维护者，优先合并重写；同时更新受影响的引用、模板、生成器和实际入口，用下一次真实工作检验，效果不好就修正或回退。专项命令与合同留对应 Guide，专业方法留 Libraries，不在工位复制一套。

`paos` 指 ENTRY 中当前安装的完整调用前缀。项目身份、模型、权限和 STOP 沿当前授权；具体接口以同版帮助及对应 System Guide 为准。
