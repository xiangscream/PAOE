## PAOE · Agent 运行指南

PAOE 是 Human 和多名 Agent 共同工作的本地环境。Human 给出目标、做关键取舍；Agent 结合已有经验和方法独立推进，需要配合时直接找同事。Work 只作临时协作的口头称呼，不显化为编号或状态机；长期状态留在业务原件、个人 TODO 和已有 CAT 房间中。

| 核心职责 | 去哪里 |
| --- | --- |
| 恢复工位、联系同事、查运行规则 | **System** 提供工位入口、联系工具、CAT、通用指南和模板。 |
| 查当前业务口径、依据、团队分工 | **Projects** 各库保存最新口径（`INDEX`）、长期岗位唯一正文（`TEAM`）、阶段成果（`HISTORY`）。 |
| 查已有做法、沉淀通用能力 | **Libraries** 保存现行主方法（Workflow/Skill）与本机工具入口（Tool Catalog）。 |
| 检索跨项目经历、原话与取舍 | **EXM** 保存短共同背景与跨项目记忆。先检索定位，再回到原件上下文。 |

### 1. 从当前任务恢复

新会话、接班或压缩后，从本人 ENTRY 取得 CLI 前缀。已登记接收器的 Codex 本人在原 Desktop 执行 `orient <project> <本人Sxxx> --resume`；其他 Harness 执行 `orient <project> <本人Sxxx> --read`（v0.1 拟议提供统一 `context read` 供按检查点装载与显式补读，具体参数待定稿）。Rooter 从安装级 ENTRY 执行 `attention rooter-show --resume`。

阶段开始、新目标、恢复与压缩后，完整阅读必要规则、本人 Current、必要业务入口与短「共同背景」；同一执行阶段内复用已选底稿，不把静默后台更新中途塞进正在推进的任务，Human 新输入与本房有效角色变化在下一次动作边界及时带入。**遇事不决，先查 EXM**（v0.1 拟议提供统一 `context search` 按库筛选检索）；将仍适用的判断写进当前方案并链接原件。

项目用编号（如 `3002`），成员用全局员工号（如 `S070`），工位在 `Workstations/Sxxx`。恢复时同时扫本人承担责任的 CAT 房间（读挂载 INDEX、临时角色卡与未读增量，实读后推进游标；细则见 System CAT 操作指南）。

### 2. 把责任落到 TODO（含 0 类综合工作）

所有行动以本人工位唯一生效的 `TODO.md`（v4）为准。新任务接入对应 Task，确有新责任时新增。Current 只写当前焦点：

- **目标（Objective）**：本次要交付的结果。
- **下一步（Next action）**：一项能直接开始的具体动作。
- **等待（Waiting）**：缺谁的什么输入、收到后如何接续；无则留空。
- **在途（Inflight）**：已发出而尚未完成的操作；未来计划不算在途。

本人维护 TODO：改 Current 用 `attention todo-update`，改 Tasks/Pinned 用带原文指纹的 `todo-write`，冲突先重读。

**0 类综合工作（以 `0` 开头的真实新输入）**：先由临时负责人在本人 TODO 登记规划并给出团队计划 → 经 **Human 第一次放行** 后建本目标专用 CAT 并邀请成员 → 成员在房内完善临时角色卡（拟职责、拟 TODO 安排与成果入口，放行前仅存房间/计划原件，不提前写入正式执行 Task）→ 经 **Human 第二次放行** 后接入本人正式执行 Task 并全员开工。放行后 Human 在房内保存纠正直接生效并提醒本人，Agent 在原授权内更新进展照常进行，仅实质改动目标、参与人、职责或交付范围时交受影响差异。普通非 0 类任务按原授权直接执行。

### 3. 用已有方法和工具推进

已授权的简单修改，由执行者自查后直接交付。

- **查方法与工具**：准备设计流程、配置工具或首次处理某类产物时，先从 Libraries 找现行主方法（`paos library search "动作或产物"`），本机工具沿 `library tools` 登记入口调用。
- **长期岗位与临时角色**：长期岗位与 Harness 分工统一读 `TEAM.md`（或 `paos peers`），不在工位私自重写；本轮协作的临时角色与安排读 CAT 角色卡与本人 Task。技术问题直接找负责同事，安装与原生接收找 Rooter，方向分歧与跨组协同找 Coordinator。

### 4. 阶段交付与收尾重读

修改任何文档，遵守“**云端或项目原件为唯一事实源、写前保护人工编辑、写后必须回读验证**”。

- **显式阶段交付 ≠ 整任务完成**：完成一段业务后，通过显式阶段交付入口提交成果原件、意图来源、本次变化与下一步/等待（v0.1 拟议 `stage deliver`，中间阶段只更新结果与下一步，整项完成才走 `mail result` 结束 Task）。普通回合停止（Stop）不是验收，不会自动归档或关房。
- **成果归位与变化接入**：录音、下载与原料归入对应主题来源，长期成果更新回原主题正文（飞书云端原件保持权威，本地摘要标明日期与来源），已结束且无依赖的过程件移入库外 `D:/PAOE-History` 并留 `MOVE-MAP.md`。项目原话与成果随实际变化接入 EXM（Human 直接参与的任务按 `session-extraction` 保留原话）。
- **收尾重读与压缩**：每完成一阶段，核对项目 INDEX 与规则变化，按需更新 Current 并重读最新必要原文。压缩前固化 Current、来源与在途状态，沿宿主正常入口压缩后从原件恢复。

### 5. 交接、简明提醒与 CAT 协作

- **安静接手与清晰唤醒**：被唤醒后先实读原信，确认能负责即安静接手并关联本人 Task（Mail 与 Task 关联即向发件人显示「已接手」，是否切换 Current 由本人按优先级决定）。需下游行动时用 `agent send --remind` 一次交清材料、原件链接与下一步；发件人标题应写清业务含义，提醒优先说清“谁发来什么、下一步做什么”，原信编号退到末行。普通交付后发件人解除等待即可，省去礼节性「收到」。
- **CAT 协作与关房**：同一目标达到 4 名 Agent 或需多方开放共写时开 CAT（普通发言静默，点名只叫需回应者）。CAT 在线仅表示会主动回看本房；结束本段循环即改离线（`offline` ≠ `left`），后台作业状态另行显示且不随阶段停止取消。仅为本目标单独建立的专用房在约定验收通过后自动关闭（v0.1 拟议 `task accept`），共享讨论房由负责人正常关闭。
- **持续改进**：发现小问题顺手修当前事，通用改进交方法维护者统一更新，不在工位复制多套。
