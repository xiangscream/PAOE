## PAOE · Agent 运行指南

### 1. 从当前任务恢复

新会话、接班或压缩后，从本人 ENTRY 取得 CLI 前缀，直接执行 `orient <project> <home> --read`，将当前 AGENTS、项目 INDEX、本人 ENTRY/TODO 的完整输出读入本轮上下文；再读当前任务需要的输入与成果，继续行动。摘要只帮助定位。Rooter 直接读本人工位和 System 入口，不虚构项目。

从本人 TODO 和发给本人的输入确定下一动作，同事记录用于补事实。新消息未明确替换原任务时，处理后回到原主线；已完成的旧议题只按需查结果。

### 2. 把责任落到 TODO

需要行动的新输入或返修，先写入本人 TODO 的一个未完成 Task，校准 Current，再推进。Pinned 留持续要求，Tasks 留行动和结果，Current 只写现在要做的事：

- 目标：本次要取得什么结果。
- 下一步：一项能直接开始的动作。
- 等待：缺谁的什么输入、收到后怎样继续；没有就留空。
- 在途：已经发出而尚未完成的操作；未来计划不算在途。

本人维护 TODO。只改 Current 用 `attention todo-update`；改 Tasks/Pinned 用同版 `todo-write` 和原文指纹，冲突先重读。状态、时间和完成结论取自实际结果。读信、处理 Notice、完成任务分别记录。

### 3. 用已有方法和工具推进

熟悉的小事直接做。不熟悉的任务先用 `paos library search "任务关键词"` 找 Workflow/Skill，实读命中的 `source_path`，采用对本任务有帮助的做法。工具用 `paos library tools` 找本机入口，确认命令所属环境和配置后调用；一个环境缺配置时，先找已登记的可用入口。

路径取 ENTRY、登记或真实返回值；普通操作先查同版 `--help`，不靠翻源码重新发现接口。找不到公开入口或出现错误，保留具体断点并找适当维护者，继续其他可执行部分。需要同事时读 TEAM 或 `paos peers`：业务取舍找 Coordinator，安装和原生接收找 Rooter，专业问题直接找 TEAM 中对应负责人。

### 4. 产出时一并整理

采用下载、录音或导出时，将业务原件归入Project材料目录；跨项目可复用的方法与参考资料按Libraries既有收纳规则归位并关联入口。修正引用，云端权威原件保留稳定链接。完成任务时在本人 TODO 留下结果和原件入口，再按现有方式归档完成项。

项目合成人读取成员已完成 TODO 和成果，按业务主题归并到 HISTORY，记录有价值的阶段结果、关键判断和经验；同步 INDEX 的最新业务口径与成果入口，并清理已结束的过程材料。日常总结时顺手更新，同一主题补充原条目，详细过程沿原件回查。

AGENTS 维护运行规则，INDEX 维护当前业务，TEAM 维护成员分工与 Harness，HISTORY 汇总阶段成果。共享文件明确一位合成人。

项目库保留当前业务、有效材料和接续入口。结束且没有在途依赖的过程件及旧 Mail/Notice，按现行文件/接口指南移到库外历史，库内留短索引。直接移动已确认的准确路径；报错就停该次移动，不接着删除源件。

### 5. 交接并持续改进

需下游行动时，用 `agent send --remind` 交成果、下一责任和原件。读实际回告及产物后接续；提醒受理尚不等于对方完成。未知交付先查原消息，不重发。多人讨论用 CAT，行动回本人 TODO，结论回项目。

交付一个阶段后，继续当前授权内能做的下一步；只有没有可执行责任或确有外部依赖时等待。压缩前保存 Current、成果和在途操作，沿 Harness 正常入口压缩，完成后回第 1 步。

发现重复劳动、失效入口或难用说明，先解决当前事，顺手修已授权的小项。可复用改进回唯一方法维护者，优先合并重写；同时更新受影响的引用、模板、生成器和实际入口，用下一次真实工作检验，效果不好就修正或回退。专项命令与合同留对应 Guide，专业方法留 Libraries，不在工位复制一套。

`paos` 指 ENTRY 中当前安装的完整调用前缀。项目身份、模型、权限和 STOP 沿当前授权；具体接口以同版帮助及对应 System Guide 为准。
