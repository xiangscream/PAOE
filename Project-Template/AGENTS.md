## PAOE · Agent 运行指南

PAOE 是 Human 和多名 Agent 共同工作的本地环境。Human 给出目标、做关键取舍；Agent 结合已有经验和方法独立推进，需要配合时直接找同事。Work 只作临时协作的口头称呼，不显化为编号或状态机；长期状态留在业务原件、个人 TODO 和已有 CAT 房间中。

| 核心职责 | 去哪里 |
| --- | --- |
| 恢复工位、联系同事、查运行规则 | **System** 提供工位入口、联系工具、CAT、通用指南和模板。 |
| 查当前业务口径、依据、团队分工 | **Projects** 各库保存最新口径（`INDEX`）、长期岗位唯一正文（`TEAM`）、阶段成果（`HISTORY`）。 |
| 查已有做法、沉淀通用能力 | **Libraries** 保存现行主方法（Workflow/Skill）与本机工具入口（Tool Catalog）。 |
| 带入跨项目共同记忆，找回原话和取舍 | **EXM** 提供开工时先读的短共同背景，以及可按需检索与追读的经历正文和原件。 |

### 1. 从当前任务恢复

新会话、接班或压缩后，从本人 ENTRY 取得 CLI 前缀。已登记接收器的 Codex 本人在原 Desktop 执行 `orient <project> <本人Sxxx> --resume`；其他 Harness 执行 `orient <project> <本人Sxxx> --read`（`context read <本人Sxxx> [--task <TaskID>] [--reason startup|resume|compact|stage|request] [--source <原件>]` 供按检查点装载与显式补读）。Rooter 从安装级 ENTRY 执行 `attention rooter-show --resume`。

开始新任务、进入新阶段或压缩后恢复规划时，先恢复必要规则、本人 Current、当前原输入与必要业务入口，再读完页首「共同背景」，把跨项目重要经历和联系带入当前上下文，然后写 TODO 或计划；同一执行阶段内复用已选底稿，不把静默后台更新中途塞进正在推进的任务，Human 新输入与本房有效角色变化在下一次动作边界及时带入。

结合当前任务，主动联想既有结论、可复用的成果和做过类似事的同事。需要细节时，沿主题或日期追读，或用页首的本机 EXM 方法搜索（只找经历用 `-c exm`；`context search` 供按库筛选检索）。读关键原话、发生条件和后续纠偏，结合项目 INDEX 判断哪些仍适用；把会改变计划、正文或协作的发现用到当前工作并链接原件。需要同事帮助时，查 TEAM 后带着具体问题联系。

项目用编号（如 `3002`），成员用全局员工号（如 `S070`），工位在 `Workstations/Sxxx`。恢复时同时扫本人承担责任的 CAT 房间（读挂载 INDEX、临时角色卡与未读增量，实读后推进游标；细则见 System CAT 操作指南）。

### 2. 把责任落到 TODO（含 0 类综合工作）

所有行动以本人工位唯一生效的 `TODO.md`（v4）为准：零散事项单列，并行工作在现有 Task 的 `source_refs` 内标 `work-group:<工作名>` 与对应 CAT 标签（如 `cat-role:<room>` 或 `cat-room:<room>`）归组，同组待办、来源与成果自成范围，收尾只取本组；角色卡直接映射后端该组安排与成果，不维护第二份 TODO（Work 保持软流程，不建注册库、编号或状态机）。新任务接入对应 Task，确有新责任时新增。Current 只写当前焦点：

- **目标（Objective）**：本次要交付的结果。
- **下一步（Next action）**：一项能直接开始的具体动作。
- **等待（Waiting）**：缺谁的什么输入、收到后如何接续；无则留空。
- **在途（Inflight）**：已发出而尚未完成的操作；未来计划不算在途。

本人维护 TODO：改 Current 用 `attention todo-update`，改 Tasks/Pinned 用带原文指纹的 `todo-write`，冲突先重读。

**0 类输入与临时负责人**：收到 Human 以 `0` 开头的真实新输入（非引用或历史转述）时，不直接开工，先作为临时负责人完整载入本项目 [Work 流程指南](WORK-LEAD.md)（`paos context read <本人Sxxx> --source WORK-LEAD.md`），按“对齐具体使用链 → 团队计划放行 → 建 CAT 与角色卡 → 角色卡放行 → 全员开工”推进；所有 PAOE 业务决定由 Human 在对话或可选界面表态一次即生效，不重复弹窗（Hook 信任与系统权限弹窗不属业务节点）。普通非 0 类任务按原授权直接执行。

### 3. 用已有方法和工具推进

已授权的简单修改，由执行者自查后直接交付。

- **查方法与工具**：准备设计流程、配置工具或首次处理某类产物时，先从 Libraries 找现行主方法（`paos library search "动作或产物"`），本机工具沿 `library tools` 登记入口调用。
- **长期岗位与临时角色**：长期岗位与 Harness 分工统一读 `TEAM.md`（或 `paos peers`），不在工位私自重写；本轮协作的临时角色与安排读 CAT 角色卡与本人 Task。技术问题直接找负责同事，安装与原生接收找 Rooter，方向分歧与跨组协同找 Coordinator。

### 4. 阶段交付与收尾重读

修改任何文档，遵守“**云端或项目原件为唯一事实源、写前保护人工编辑、写后必须回读验证**”。

- **显式阶段交付 ≠ 整任务完成**：完成一段业务后，通过显式阶段交付入口提交成果原件、意图来源、本次变化与下一步/等待（`stage deliver <本人Sxxx> --task <TaskID> --id <交付ID> --artifact <成果> --intent <意图> --result "<结果>" (--next "<下一步>"|--waiting "<等待>") [--current]`；中间阶段只更新结果与下一步，不提前结束整项 Task；整项完结时，有原 Mail 的任务走 `mail result`，普通 Task 按约定验收收口）。普通回合停止（Stop）不是验收，不会自动归档或关房。
- **本工作介入带回 CAT 与收尾离席**：参与已组织开展的 Work 时，若与 Human 直接对话并收到本工作介入，由本人判断范围后将相关原话、时间与来源带回本房 CAT（房内已有发言不重复转帖，转述不伪装 Human）。交清本段成果、经历与未完交接即可 `left` 离席；临时负责人沿 CAT 介入与已有成果统一形成一份本工作意图稿/述职，待 Human 明确通过（`accept-goal` 一次决定、不重复弹窗）后再结束整体任务并关闭对应专用 CAT（详规见 [WORK-LEAD.md](WORK-LEAD.md)）。普通工具调用、已授权子任务与中间阶段交付按原授权连续推进，不设为 Human 审批门。
- **成果归位**：录音、下载与原料归入对应主题来源，长期成果更新回原主题正文（飞书云端原件保持权威，本地摘要标明日期与来源），已结束且无依赖的过程件移入库外历史目录并留恢复入口；清理本人TODO和工位，不另造一份过程汇总。
- **任务收尾与经历回流**：本人TODO中的一项Work或一项独立TODO完成时，将本项相关的Human原话、关键纠偏、成果及值得以后复用的经历带来源交EXM当前整理者（沿EXM TEAM定位），作为本项结尾动作。Work复用临时负责人的统一意图稿与成果，独立TODO由执行者交必要原话和简短结果；成员已交的材料不重复收集。没有长期新增不交空稿，也不把普通回执写成经历。取消S053每日联动各Agent索稿的做法；录音、业务日结和双机同步沿原职责。EXM按主题整理原话与认识，Human零散想法进入“心得/Tips”，围绕主题形成的哲学保留来源与演变；不把Agent推断写成Human原话。日视图复用已有材料，普通更新安静完成。项目INDEX仍维护当前业务口径，下一次开工或阶段切换主动读共同背景并追相关原件。
- **收尾重读与压缩**：每完成一阶段，核对项目 INDEX 与规则变化，按需更新 Current 并重读最新必要原文。压缩前固化 Current、来源与在途状态，沿宿主正常入口压缩后从原件恢复。

### 5. 交接、简明提醒与 CAT 协作

- **安静接手与清晰唤醒**：被唤醒后先实读原信，确认能负责即安静接手并关联本人 Task（Mail 与 Task 关联即向发件人显示「已接手」，是否切换 Current 由本人按优先级决定）。需下游行动时用 `agent send --remind` 一次交清材料、原件链接与下一步；发件人标题应写清业务含义，提醒优先说清“谁发来什么、下一步做什么”，原信编号退到末行。普通交付后发件人解除等待即可，省去礼节性「收到」。
- **推进节奏与优先级**：Human 调整优先级即校准 Current；交付后有已授权下一步就继续推进，真实等待只暂停对应事项。
- **CAT 协作与关房**：组织一项 Work 即建并关联 CAT（不再等 4 人；普通零散任务不变成 Work），多方开放共写时也可开 CAT（普通发言静默，点名只叫需回应者）。CAT 在线仅表示会主动回看本房；暂停看房记 `offline`，交清本段成果与交接后可 `left` 离席（离席不丢成果、原身份或再邀请能力），后台作业状态另行显示且不随阶段停止取消。仅为本目标单独建立的专用房在约定验收通过后自动关闭（`task accept`；面向 Human 验收的整体协作须按第 4 节由负责人单稿述职并经 Human 明确通过后再结束并关房），共享讨论房由负责人正常关闭。
- **持续改进**：发现小问题顺手修当前事，通用改进交方法维护者统一更新，不在工位复制多套。
